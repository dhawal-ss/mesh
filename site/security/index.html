Security

Report a vulnerability confidentially

Use GitHub private vulnerability reporting for Mesh client, backend, or release-pipeline vulnerabilities. Do not file a public issue containing exploit details, credentials, invitation capabilities, private room IDs, or user data.

The repository owner acknowledges reports, coordinates remediation and disclosure, and credits reporters when requested and safe. No response-time SLA is promised before the production beta exists.

Include

  • the affected Mesh version and operating system;
  • reproduction steps with secrets and personal data removed;
  • the impact and whether the issue is actively exploited;
  • a safe way to coordinate follow-up.

Release trust

Reviewed releases provide checksums and SBOMs. A consumer beta additionally requires a trusted Authenticode signature and timestamp on Windows. macOS and Linux builds are unsigned third-party software: macOS is not notarized, so Gatekeeper blocks the first launch until you approve it in System Settings. The Tauri updater requires a separate signing key and must reject invalid manifests and signatures.

Provider incidents

Report an incident in an independently operated account service to that operator. A community-hosted service's abuse and incident contact belongs to its community owner.
